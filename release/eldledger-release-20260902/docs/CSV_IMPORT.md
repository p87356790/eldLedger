# CSV 거래내역 가져오기 및 자동 분류

카드·은행 CSV를 가계부 거래로 들이고, 가맹점 키워드로 분류·개인/사업·태그를 추천한다. 사용자는 차변/대변/분개를 보지 않는다. 확인 후 저장하면 기존 `Transaction` → 자동 `JournalEntry` 경로를 그대로 탄다.

구현 위치:

| 역할 | 위치 |
| --- | --- |
| 열 매핑 프로필 | `ImportProfile` |
| 가맹점 자동 분류 규칙 | `AutoCategoryRule` |
| 파싱·미리보기·일괄 등록 | `backend/app/services/csv_import_service.py` |
| API | `POST /api/v1/import/preview`, `POST /api/v1/import/commit`, `/api/v1/import/rules` |

금액은 항상 **원(KRW) 정수**이다. float를 쓰지 않는다.

---

## 1. 가져오기 흐름

```text
CSV 업로드 + 결제수단(계좌) 선택
        ↓
열 매핑 (프리셋 / 저장한 프로필)
        ↓
인코딩 감지 후 파싱
        ↓
미리보기 (중복 표시, 자동 분류 추천)
        ↓
사용자가 구분·분류를 고치거나 건을 빼기
        ↓
일괄 Transaction 생성
        ↓
건마다 자동분개 (차변 합 = 대변 합)
```

미리보기는 DB에 쓰지 않는다. 등록만 거래를 만든다.

---

## 2. 파일 규칙

- 확장자 `.csv`, 최대 5MB, 최대 2,000행(헤더 제외).
- 인코딩은 UTF-8(BOM 포함), CP949, EUC-KR 순으로 디코드해 처음 성공한 값을 쓴다.
- 구분자는 콤마 또는 탭. 헤더가 있으면 `csv.Sniffer`로 추정하고, 실패하면 콤마.
- 빈 행은 건너뛴다.

---

## 3. 열 매핑 (`ImportProfile`)

프로필은 조직(장부)별로 둔다. 코드 프리셋을 장부에 복사해 두고, 사용자가 저장한 매핑도 같은 테이블에 둔다.

| 필드 | 의미 |
| --- | --- |
| `date_column` | 거래일 |
| `merchant_column` | 가맹점·적요 |
| `memo_column` | 추가 메모 (선택) |
| `amount_column` | 단일 금액 열 |
| `outflow_column` / `inflow_column` | 출금·입금이 나뉜 경우 |
| `type_column` | 출금/입금 구분 열 (선택) |
| `amount_mode` | `UNSIGNED_EXPENSE` · `SIGNED` · `SPLIT` |

### 3.1 금액 모드

| 모드 | 해석 |
| --- | --- |
| `UNSIGNED_EXPENSE` | 양수 금액을 지출로 본다. 카드 이용내역. |
| `SIGNED` | 음수·괄호 금액은 지출, 양수는 수입. |
| `SPLIT` | 출금 열 > 0 이면 지출, 입금 열 > 0 이면 수입. |

### 3.2 표준 프리셋

| 키 | 이름 | 기본 열 | 모드 |
| --- | --- | --- | --- |
| `generic` | 일반 | 날짜, 금액, 가맹점 | SIGNED |
| `card_kr` | 카드 | 이용일자, 이용금액, 가맹점명 | UNSIGNED_EXPENSE |
| `bank_kr` | 은행 | 거래일자, 출금, 입금, 적요 | SPLIT |

헤더가 프리셋 열 이름과 맞으면 미리보기에서 그 프리셋을 고른다. 아니면 `generic`과 헤더 별칭(거래일, 내용, 출금액 등)으로 맞춘다.

### 3.3 금액 파싱

`₩`, `원`, 콤마, 공백을 제거하고 정수로 변환한다. `(12,000)` 과 `-12000` 은 음수. 소수점이 있으면 소수점 아래는 버린다(원 미만 없음).

## 4. 중복 감지

지문:

```text
SHA-256( 날짜ISO | 금액정수 | 가맹점정규화 )
```

가맹점 정규화: 앞뒤 공백 제거, 연속 공백 1칸, 대소문자 무시(`casefold`).

비교 대상:

1. 같은 파일 안 앞선 행
2. 같은 장부의 확정(`CONFIRMED`) 거래 — 날짜·금액이 같고, 메모를 같은 방식으로 정규화한 값이 가맹점과 같음

중복 의심 건은 미리보기에서 표시하고, 기본값은 **등록에서 제외**이다. 사용자가 다시 넣도록 켤 수 있다.

## 5. 자동 분류 (`AutoCategoryRule`)

| 조건 | 결과 |
| --- | --- |
| 가맹점 키워드가 가맹점명에 포함 (대소문자 무시) | 분류 |
| (선택) 결제수단 계좌가 미리보기에서 고른 계좌와 같음 | 개인/사업 |
| | 태그 목록 |

`sort_order`가 작을수록 먼저 맞춘다. 비활성 규칙은 쓰지 않는다. 맞춘 분류의 수입/지출이 행의 거래 유형과 다르면 그 규칙은 건너뛴다.

규칙이 없으면 분류는 비워 두고, 구분은 `PERSONAL`로 둔다. 등록 전에 분류가 없는 지출·수입은 저장하지 않는다.

거래 입력 화면의 자동 추천도 같은 규칙을 쓸 수 있다. 이번 범위의 1차 적용처는 CSV 미리보기이다.

예 (Requirements §29):

```text
조건: 가맹점 키워드 = 쿠팡, (선택) 결제수단 = 국민카드
결과: 분류 = 사무용품, 구분 = 사업, 태그 = 해당하는 태그
```

---

## 6. 거래 생성

등록된 각 행은 기존 거래 저장과 같다.

- `payment_account_id`: 미리보기에서 고른 계좌/카드
- `memo`: 가맹점명 (추가 메모가 있으면 `가맹점 · 메모`)
- 항목 1줄: 분류, 금액, 구분
- 태그: 규칙 또는 사용자가 고른 `tag_ids`
- `AccountingService.post_transaction`으로 확정 분개

이체 유형은 CSV에서 만들지 않는다.

한 건이 실패해도 나머지는 계속 넣고, 응답에 실패 행을 모은다. 성공 건은 이미 분개된 상태이다.

## 7. API

### `POST /api/v1/import/preview`

`multipart/form-data`: `file`, `account_id`, `organization_id`(없으면 로그인 사용자의 장부), `profile_id`(선택).

응답: 인코딩, 헤더, 적용된 프로필, 행 목록(중복·추천 여부, 오류), 건수 요약.

### `POST /api/v1/import/commit`

JSON: 계좌, 사용자가 확인한 행. `skip: true` 인 행은 만들지 않는다.

응답: `created`, `skipped`, `failed` 목록.

### `/api/v1/import/rules`

로그인 사용자의 장부 범위 CRUD.

### `GET /api/v1/import/profiles`

프리셋 + 저장된 열 매핑. 장부에 프리셋이 없으면 생성한다.

모든 엔드포인트는 JWT가 필요하다.
